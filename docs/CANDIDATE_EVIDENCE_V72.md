## 启动与使用

双击项目根目录 `project-agent.cmd`，或在 PowerShell 执行：

```powershell
Set-Location -LiteralPath '<repo>'
.\project-agent.cmd
.\project-agent.cmd status
Start-Process 'http://127.0.0.1:8802/'
```

启动器现指向 `research72.control`。继续使用已有隔离环境和本地固定权重，不安装或下载依赖。后台启动返回“started”不等于已经监听端口；原推荐组件拟合及模型首次装载需要等待，请以 `status` 的 ready 为准。8791 阅读工作台保留原样。

1. 输入需求、选择任务类型与服务端画像，整理并核对原问题、可编辑查询及限定条件，勾选两项确认。
2. 执行真实 Agent。左侧“本次候选与排序依据”只显示该作业实际搜索/推荐工具返回的论文，右侧继续显示原生事件时间线。
3. 卡片列出每个来源的原始排名、实际分数、ID、版本、来源链接、发表/可用日期，以及读取请求、成功读取和引用状态。同一论文可保留多个来源及各自名次，不重新排序冒充原始名次。
4. 点击卡片的调用编号/摘要读取编号，定位右侧真实调用；时间线及引用中的“定位候选”可返回对应卡片。
5. 若要检查算法，点击“运行独立诊断”，展开独立区域。切换方法只切换已计算的诊断结果，不改变运行中任务的工具或候选。
6. 历史下拉新增阶段71的五条真实作业。载入只读回放，不启动模型；旧方案不能直接重新提交，需重新整理并确认。保留的空结果失败仍显示8次模型调用和未完成提交。

需求、查询、画像或任务来源变化会清空旧候选和诊断。先前执行记录仍按原来源保留，不把它们归给新需求。对迟到的接口响应也做请求代次核对，防止旧响应重新填回列表。

## 什么是实际证据

实际候选来自当前作业原生 trace，执行中来自同一作业的 `tool_returned` 事件，结束后以权威结果核对。新增接口只读这些记录，不调用 session 工具，不增加模型预算，也不把解释或诊断结果写入模型输入。

- 搜索原始分数保留工具响应中的 `score`。另外复用同一冻结 AsOfBM25 组件的 SQLite FTS5 `highlight()` 与 `bm25()`，核对实际标题/摘要匹配的表面词形及分数。Porter 词干分析可能让查询词与显示词形不同；这些不是逐词 BM25 分数贡献。
- 推荐沿用原工具的 `algorithm_evidence`：实际画像内容余弦、最相近训练历史论文、该论文余弦及原生分数。缺字段显示未提供；没有生成式推荐理由。
- 冷启动实际推荐继续原生流行度回退；画像余弦留空，不能把流行度当作内容相似度。
- 版本和日期来自冻结目录，明确属于展示补充，不冒充工具本来已返回的字段。原始 `source_paper` 保留，可逐字段核对。
- “已请求读取”只表示观察到读取请求；“已读取”要求工具成功；“已引用”要求本条最终接受的回答包含该论文。运行中已验引用标为暂验，结束后重新核对。未选中、未读或未引用不等于不相关。
- 仅检索/推荐接口返回标题和证据，不因此标记“读过摘要”；引用仍由原生读取与原文核验门槛控制。回答保留实际摘录、ID、版本和链接。

## 独立算法诊断的冻结条件

默认 Agent 搜索仍为原 BM25，推荐仍为原内容方法。新诊断不作为 Agent 工具，不替换默认，不进行参数选型。

| 方法 | 实际实现 | 范围 |
| --- | --- | --- |
| BM25 召回 | 原 `AsOfBM25.search` / SQLite FTS5；标题权重2、摘要权重1 | 相同时点可用且未读的目录，Top10 |
| 内容召回 | 已拟合的 TF-IDF `transform(query)`，sklearn `linear_kernel` | 相同目录与过滤，只保留正查询余弦的Top10 |
| 共享池查询排序 | 联合两种召回结果，按查询余弦排序 | 同一固定候选池，最多20篇 |
| 共享池画像重排 | 原 `rank_indices(..., 'hybrid', components=...)` 的RRF | 同一固定池；查询权重0.75、画像权重0.25，RRF常数60 |

两种召回比较候选集合与重合度，不能将其差异归因于重排。共享池两种排序完整保存同一批ID，页面显示前10名及相对名次；原生RRF函数只返回顺序，融合标量留空，不混加 BM25 与余弦原始分数。最近历史论文只是实际内容相似依据，不能证明满足需求。

冷启动或零内容画像的**独立重排诊断**保持共享池查询排序，不注入流行度，也不伪称个性化有效；这与实际推荐工具的原生流行度回退明确区分。推荐任务没有搜索词，不暗中执行搜索对照。内容词表无匹配、查询余弦全零时，不用零分论文补足Top10。

服务初始化、任何诊断前写入 `data/stage72-diagnostics/protocol.json`：目录/文本哈希、词表/IDF哈希、原TF-IDF参数、训练截止、候选池规则、排序规则与融合参数。每次请求保存原需求、实际查询、服务端画像、时点、可用未读集合哈希、候选池ID/哈希、全部排序、词项乘积和耗时。

继续使用冻结10,000篇目录，推荐时点 `2025-02-23T05:28:26.401006+00:00`，画像训练截止 `2024-10-27T18:52:32.337704+00:00`。论文可用时间仍是原v1提交日加宽限的假设，不能宣称已证实历史真实入库。TF-IDF只用既有训练期词表/IDF，查询不会重新拟合；它是词汇内容检索，不是新增语义向量模型。复杂语义限定继续沿用v71的明确未核验提示。

## 文件、接口与复跑

新版本代码在 `research72/`；原生执行继续使用 `research71.worker`。新任务分别写 `data/stage72-custom/` 与 `data/stage72-lab/`，诊断写 `data/stage72-diagnostics/`。仅在执行器结束且完整结果稳定后，原子写入解释审计文件到对应作业的 `candidate-evidence-<run>.json`，不改原输入、事件和结果。诊断失败记录也保存。

- `POST /lab/v72/diagnostics/custom`：严格字段；已确认方案绑定查询/画像/时点。
- `POST /lab/v72/diagnostics/preset`：严格预设白名单。
- `GET /lab/v72/jobs/{id}/candidates?run_index=0`：当前作业实际候选，支持原生多任务索引。
- `GET /lab/v72/retained` 及对应结果/候选路由：五个明确白名单的阶段71保留案例；不接受文件路径。
- `GET /lab/v72/examples/{key}/candidates`：原三条历史回放的只读解释。

服务运行时可执行低成本检查：

```powershell
.cache\stage17\runtime\Scripts\python.exe -E -s -m research72.http_regression
.cache\stage17\runtime\Scripts\python.exe -E -s -m research72.invariant_checks
.cache\stage6-env\Scripts\python.exe -E -s -m research72.token_budget_checks
```

`acceptance.py` 用独占目录防止覆盖原诊断验收；`budget_checks.py` 同样保护原工具失败记录。`browser_acceptance.cjs` 会真实启动一次模型，不是健康检查；浏览器脚本需要专用Edge/CDP环境。保留每实例16个作业、64份方案及事件读者上限；独立诊断每实例最多64次。

同一服务实例内仍支持SSE断线/刷新恢复；服务重启后的内存登记恢复尚未实现，事件与结果文件保留，不自动重跑。当前是回环本机服务，没有公网部署、访客画像或新增线上安全承诺。

## 开源比较与实现边界

直接复用现有 SQLite FTS5/AsOfBM25、已装 sklearn、冻结推荐/RRF、原生Agent/事件及现有DOM组件。比较 Pyserini 的Lucene检索/RRF、OpenSearch的ExplainPhase和sklearn稀疏余弦源码；Pyserini/OpenSearch需要新Java/服务/索引，适配与运行成本高，本轮未安装或复制它们。解释借鉴“从原生打分取证”的方式，不用模型生成理由。

仓库维护状态、固定源码blob/引用版本、许可证、安全与适配取舍见 `reports/stage72/research.json` 与 `research-sources.json`。仓库未归档不是安全认证。实现及验收插曲见 `implementation-notes.json`：首次启动尚未ready就探测、重复前台诊断启动遇端口占用、一次CLI引用错误、补充脚本继承了推荐任务类型，以及证据原子保存时误导入仅在执行环境存在的模块导致接口500；改用标准库临时文件替换后复核，原固定执行完整保留。上述情况均保留并纠正，没有因此追加模型推理或隐藏模型失败。
