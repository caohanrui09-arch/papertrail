# Papertrail 小批真实试用任务卡

当前状态：**页面与材料已准备，真人试用按用户选择留待之后。** 本轮自动验收不算真人试用，也不算论文相关性判断。

## 准备与入口

启动论文工作台与Agent服务，打开 <http://127.0.0.1:8791/trial.html>。这是当前电脑的本机试用版，朋友可在同机操作；没有生成公网托管链接。

建议先邀请1–3位朋友，每位使用独立浏览器隐私窗口。填写P01等化名，阅读保存说明并主动同意，再点击新建试用；不要填写姓名、邮箱或联系方式。**记录只存在当前窗口，关闭隐私窗口前先导出。** 本页记录与收藏备份、盲标标签分开，不会自动上传操作反馈或采集浏览历史。

主持人可以展示目标，尽量让参与者自己找入口。若给予提示或全程带着操作，应如实选择帮助等级；不要代替参与者填成独立完成，也不要删除卡住或跳过的尝试。

## 五张任务卡

| 任务 | 请参与者完成的操作 | 可记录的证据 |
| --- | --- | --- |
| 1 找到并读一篇 | 搜索生成式检索相关论文，选择一篇并打开原摘要 | 标题/ID、选择过程、实际到达的位置 |
| 2 核对版本来源 | 找到论文ID、版本与原始来源链接 | ID、v1版本、如何核对摘要对应版本 |
| 3 需求交给Agent | 从工作台带入需求，确认原问题、画像和目录截止时间；到确认页即可，不必执行模型 | 查询是否保留，是否注意到目录/画像差异 |
| 4 沿引用找读取 | 在实验台载入“固定组合流程·已提交”历史记录，定位引用对应的read_paper | 读取调用编号、版本和摘录；能否识别这是历史回放 |
| 5 导出记录 | 为同一条历史任务下载Markdown和JSON并打开 | 是否找到导出入口，能否看到来源和成本 |

任务3不要求模型执行，任务4明确是历史固定流程；不要把这些观察写成模型自主决策成功或回答质量提升。

## 保存、恢复与导出

每项操作前点击“开始计时”，再使用卡片中的相关页面链接。计时是**操作墙钟时间**，包括思考和切换标签，不是接口延迟。活动任务和草稿可在同一窗口刷新恢复。时钟异常或超过3小时会保留尝试，但时长标为无效。

结果可选完成、部分完成、卡住未完成、跳过；另选是否需要帮助。选择完成时需填写具体证据。再次尝试会追加新记录，原失败保留。最多保存20个本地试用会话，每个50次尝试，不静默覆盖旧记录。

可导出当前试用JSON、Markdown，或导出本浏览器的全部试用JSON。文件含化名、主动填写的反馈、时间戳和尝试历史，分享前请查看。JSON标有协议哈希、来源和“完成由参与者自述，未独立核验”。试用页不测量Agent消耗；若参与者另外手动执行模型，成本应以那条实际任务报告为准。

## 如何整理结果

逐任务记录参与人数、参与者填写的结果、是否给过帮助、有效墙钟时间和常见阻碍。保留所有尝试、无效时间与缺失记录，说明小样本和自述性质。先修复多位参与者共同遇到的入口或理解问题，再决定是否开展下一批。

这不是相关性标注，没有0/1/2标签，不产生NDCG、MRR、CTR、语义正确率或推荐提升结论。单纯识别到版本、引用和历史回放，也不能视为需求已被模型满足。

## 自动验收边界

`/trial.html?verification=1` 是单独的自动验收空间，来源固定为 `automation_test`。普通页面来源为参与者自述 `human_self_report`，不是身份真实性认证。两者使用不同的本地存储键；自动结果不得并入真人反馈。页面没有自动邀请、发送消息或公网部署功能。
