# 状态约束Agent复现

本轮比较固定流程、未加新约束的原LLM和状态约束LLM。三者使用同一万篇原v1目录、相同绑定用户/历史时点、默认内容推荐、原摘要读取、Qwen1.5B冻结权重及预算。4个tuning、12个正式任务沿用阶段19，结果只作描述性协议/成本比较，不是未见任务、真实相关性或模型推理优势评测。

## 实际复用及边界

执行循环、JSON解析、工具分发、基础参数类型校验、逐步回调和最终校验均由现有smolagents1.22.0负责。项目只提供状态适配器：根据已观察工具结果更新当前工具注册表、可读取ID及最终引用条件。没有重写Agent循环、执行生成代码、训练新模型或安装新依赖。

框架原生schema仅供模型参考，参数类型和工具名称由原生分发校验；上下界、当前ID成员关系、引用数量/来源由项目适配器校验。这里没有token级约束解码，模型仍可生成错误JSON或已隐藏的工具名，这些都会记录。旧接口的默认k=3不改；新模型面对的接口把k设为必填、非空整数1..3，遗漏/null/布尔值不自动补正。

搜索与推荐各成功调用一次后从注册表移除；读过的ID从可选集合移除。组合任务允许两种检索顺序，保留最后一个读取名额给能覆盖另一检索来源的论文。模型仍负责选ID、选引用索引并生成final_answer；同一个模型调用可以面对多个候选ID或多个合法工具。即使只剩final_answer，也要由模型自行生成，系统不会替它提交。

工具/引用状态只来自真实响应和显式intent，不读取目标gold ID。显式intent由受控任务给定，不评价自然语言意图识别。状态约束带来的改善应归因于工程约束和状态提示；报告单一注册工具步骤、干预和拒绝，不能算作大模型独立学会了规划。

## 统一预算与完整计费

每任务最多6次应用工具尝试（含finalize）、2次检索、2次读取；框架7步，最多8次LLM调用（包含超步兜底生成），累计输入30000/输出1280token，每次至多160输出token。

约束版本在本地拦截的已解析提案也扣等价应用/检索/读取额度，禁止以未发送HTTP为由免费重试。解析失败消耗LLM调用和token；额外被拒提案、native schema错误、动作屏蔽、本地拒绝与后端拒绝分开记录。约束版本的本地扣费可比旧版更严格，绝不会获得额外执行额度。实际计算量由输出逐项报告。

超步兜底的生成照样计费，但未通过原生协议的文本不当作成功回答。没有静默替换固定流程、自动选文或自动finalize。阶段19/20所有代码和结果保留。

## 运行入口

确认原统一服务运行：

```powershell
.\unified-service.cmd status
# 未启动时：.\unified-service.cmd start
```

显式实验演示：

```powershell
.\state-agent-demo.cmd
.cache/stage6-env/Scripts/python.exe -m scripts.constrained_demo --intent search --query "graph neural networks"
```

新结果自动写入忽略的data/stage21-constraints/demo-*，成功exit0、失败exit1。服务仍在独立CPU运行时；本地Qwen只读复用既有stage6/shared CUDA环境，不声称LLM环境也完全独立。

复现实验：scripts.benchmark_state_constraints依次prepare、tuning、lock、evaluation；scripts.score_state_constraints使用冻结阶段19原评分器，通过有显式SHA映射的文件名视图读取逐字节一致原输出。llm_agent文件别名仅用于复用旧两组评分器，原JSON的实际policy字段不改，汇总恢复真实策略名。不得覆盖已有输出，缺少原私有资产时不可从空目录凭空复现。

## 预先固定的保留门槛

约束任务成功数不低于固定流程、无预算违规；相对原LLM平均耗时及总token各至少减少20%；相对固定流程平均耗时不超过5倍。当前是简单工具任务的工程点估计门槛，不是统计非劣性检验。任一失败则继续默认固定流程，结束本轮优化，不按正式结果再改提示词或任务。

正式任务已多次使用，接口响应还包含缓存/计时等运行元数据，模型观测会有变化；即使贪心生成，也不能保证不同批次逐字一致。所有绝对时间都只比较本轮同批三组，不拿旧阶段耗时直接相减。首次索引费用可能进入首个固定请求，模型装载另列；单次任务和单机结果不推断生产QPS。
