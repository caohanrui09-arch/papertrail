# 站内需求确认与盲标

当前入口：[需求确认与盲标](http://127.0.0.1:8769/label)。同一版本的[论文工作台](http://127.0.0.1:8769/)左侧也有入口。

```powershell
& '<repo>\annotation-workbench.cmd' start
```

双击 annotation-workbench.cmd 也可启动。支持 start/status/stop；启动器可从任意当前目录调用，只控制本轮网关，原论文后端保留。

## 如何开始

1. 左侧选择一条需求，先看中英文表述、核心要求和次要偏好。展开判据；推荐/组合需求另有相同的五篇阅读上下文，主题需求不附加阅读兴趣。
2. 在“确认需求”中选择确认、拒绝或待澄清，填写可用化名的判断者标识及理由。可以先保存草稿，刷新后继续。
3. 本人完成确认后，勾选来源声明并“提交需求结论”。只有确认通过的需求才能开始保存候选判断。拒绝或待澄清不会开放相关性提交。
4. 切换“判断候选”，阅读当前论文的原始 v1 摘要及来源，选择0不相关、1部分相关或2高度相关，并填写依据。
5. 尚未判断完时保存草稿；无法判断时填写原因并点“无法判断，留空”，等级保持空白。草稿和无法判断都不计入已提交覆盖。
6. 本人阅读判断后勾选声明并提交。提交后仍可修改，再次提交保留全部旧版本；“查看修订记录”可核对。
7. 切换论文或需求前先保存；未保存修改会阻止切换。需要取消本次编辑时使用“放弃未保存修改”；多页面冲突会提示加载最新版本，不静默覆盖。
8. 可导出当前空间的原生保存记录或 Label Studio 格式。未完成标注时不生成质量指标。

## 本轮材料

仅开放阶段25精修草稿中 tuning 的9条需求：生成式文档检索、物品冷启动、隐式反馈与偏差三主题，每主题搜索/推荐/组合各一条。新三方法Top10并集共155个需求—论文对；连同阅读上下文，共116篇原文经过官方原始v1响应重新解析核验。

候选池在没有标签时先准备为 provisional，需求确认后才开放同版本需求的判断。文本、核心要求或判据需要改变时，选择“待澄清”并写修改建议；开发者建立新版本及新池后再评价。站内不直接修改旧需求或旧候选池。

候选按与方法无关的固定hash排序，盲标API只返回需求、上下文、原文及你自己的保存记录。它不返回来源方法、检索名次、分数、训练用户ID或评估排名。网站其他研究页面和本机文件仍可查看算法材料，因此这是实验盲法安排，不是对本机所有者的权限封锁；标注时不要参考旧结果或排名。

## 评分与版本规则

明确满足核心要求判2；能确定部分相关而未满足完整核心判1；明确不符合判0。无法理解或证据不足时留空并说明。次要偏好不单独升降等级，来源核验本身不等于内容相关。

每次保存都绑定候选池、查询hash和递增修订号。重新提交需求结论会产生新的确认版本；旧论文判断保留，但需重新核对提交才能计入当前覆盖。恢复旧草稿不会伪造已提交状态。本站不合并不同浏览器的判断、不自动仲裁、不按模型评分代填真人记录。

当前9条全部确认、155个候选都有效提交后，才具备完整池内评价的输入条件；本轮没有新增评分入口或产生新质量分数。后续先按冻结协议计算tuning，再锁定方法，才开放后段评价。此池与旧阶段20的24条/423对不同，不能混用旧标签或旧评分入口。

本轮按桌面使用交付；手机布局的最终视觉验收按用户要求推迟到后续。桌面实际交互和HTTP验证见阶段26记录。当前Windows Computer Use因无法可靠识别浏览器地址而停止，后续界面控制需等工具恢复；这不影响手动在浏览器打开本地网址使用。

## 保存和导出

当前空间继承本地浏览器Cookie，SQLite数据保存在 data/stage26-annotation/work/annotations.sqlite3，历史修订与当前记录在同一事务内写入。盲标输入、方法排名及原文校验材料都在本机忽略目录。没有上传、外部账号认证或公网部署。

原生导出包含当前需求确认、判断、草稿、跳过和完整修订历史。Label Studio导出采用原生data/annotations/result结构，只把当前有效提交的判断写入annotations；草稿/无法判断不转成0标签。输出可用于新的标注项目；因query/pool版本不同，不能导回旧阶段20评价入口。Label Studio本体未安装或运行，兼容性声明仅指数据格式检查。

真人来源由提交者明确声明，服务器记录时间与化名；这不是身份真实性认证。不要把自动操作或模型判断标为human。

## 自动化验收空间

开发验收使用 /label?verification=1，页面顶部显示测试提示；对应请求携带测试头，服务端单独存储且来源固定为 automation_test。正常入口没有此参数。所有自动化提交都在这个空间，正式工作区和旧标注表不会增加真人计数。

查询参数/测试头只是显式分类机制，不是授权边界。浏览器空间隔离与同源检查仍生效。正式验收不得通过移除测试头把模型记录变成人工标签。
