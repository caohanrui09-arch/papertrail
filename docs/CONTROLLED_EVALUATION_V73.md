材料覆盖中英文、主题搜索、推荐与组合。24条草案继承原训练用户身份场景；本轮万篇模型使用该用户完整正反馈历史，区别于旧五篇历史子集。页面明确显示实际上下文及范围，需要重新确认。它们不是访客收藏或本人自述的兴趣画像，旧标签不复用。

算法材料统一用于**查询条件下的候选排序评价**：有明确主题查询，推荐/组合材料另带冻结画像；这不是纯推荐工具调用的效果实验。纯推荐工具的执行单独在4条Agent任务中评价。查询和限定条件只由评价作者冻结，不能视为真人已经确认；未程序化的语义条件由盲标者核对，仍可拒绝或要求澄清。

直接复用阶段26的AnnotationStore、原需求确认/摘要判断/修订/导出逻辑和Preact/JSONEditor页面，仅适配26条池、来源说明、入口与黑白灰样式。

1. 打开 `/label`，先确认需求及完整阅读场景；可保存草稿，刷新恢复。
2. 确认通过后才能判断候选。根据原摘要选择0/1/2，填写依据；无法判断则留空/跳过，不自动计0。
3. 修改需求确认版本会使旧判断需重新提交；冲突修订返回409，不静默覆盖。
4. 候选按与算法无关的固定种子hash顺序显示，隐藏候选的方法、名次与分数；同一论文在每条需求中只出现一次。
5. 当前空间独立保存；不自动合并不同浏览器的判断。评价页使用同一空间的当前有效提交。真人来源是提交者声明，不是身份认证。

这是实验盲法安排，不能阻止本机所有者在其他页面/文件查看算法排名。标注时不要参考诊断榜。自动化验收必须使用 `/label?verification=1`，页面会明确显示验证声明，原记录存入 `verification:` 名称空间，origin为`automation_test`；不进入真人质量评价。

模型辅助判断单独存于 `auxiliary/model-judgments.json`，当前为空；评价程序从不把它转成人工标签。CLI可显式导入带`origin=model`、模型名、理由及已知池ID的辅助文件，拒绝其他来源，不写人工记录库。

原LLM有8次网关执行失败、1次未执行拒绝；状态约束有0次网关执行失败、5次未执行拒绝及6次约束提案错误。这些计数可能描述同一错误的不同层次，**不能相加当独立失败总数**。解析错误会计入模型调用/Token，不一定新增网关工具轨迹；应用动作计费仍沿用原规则。

同一模型本体没有改变；约束组改变的是原生合法动作、参数schema与状态提示。3/4只能作为本组系统约束下的协议结果，不能宣称模型本体能力或语义质量提升。

本轮没有基础设施或运行时异常单元，也没有超时单元；失败均为保留的协议失败。协议具备900秒单元计时、异常及中断记录，没有以运行错误为由删除分母。本轮8个LLM单元模型装载一次，不把阶段71/72的失败或本轮重跑混入样本。

每条接受引用都核对本次成功读取、摘录子串、版本、来源URL、冻结摘要及官方缓存原响应SHA。**这是已接受引用的程序化来源核验，不是语义正确率、论文相关率、需求满足率，也不是所有模型引用提案的准确率。** 原LLM的未提交文本不作为回答展示。
