## 执行与恢复

新 research69 展示服务复用原算法、网关、预算和 research63.worker；不更改模型、不新增训练。project-agent.cmd 已指向 research69.control。论文工作台继续使用 research66 服务及原访客数据，新增展示模块 main-experience.mjs、task-preview.mjs/json/css、shared-design.css；原main-topic-accent.mjs保留。

实验台先确认 POST 已接收并取得作业编号，才切换到新结果；上一条结果可在“上一次结果已保留”中核对。查询断线时锁定重复执行，重新连接只 GET 原作业，不提交新模型请求。刷新后用当前标签页 sessionStorage 的作业编号恢复。即使提交响应丢失、前端没有编号，也可通过只读 /lab/activity 根据本次任务、策略和接收时间找回原作业。服务重启后查询不到原作业会明确说明，保留本页已有记录，等待用户手动决定是否重新执行。

当前 worker 仍在单条任务结束时返回完整轨迹。页面显示的是实际等待时长，不声称逐 token/逐工具实时事件。worker退出完整与协议提交成功分开处理；不会为模型失败自动补交答案。
