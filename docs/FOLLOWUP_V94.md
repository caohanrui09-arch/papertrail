# 追问改为"用户点选证据 + 模型只写答案"（阶段94）

日期：2026-11-24。动机：1.5B 的选择器在"总是选"和"总是拒"之间摆动（阶段92/93），两种提示都试过，8 次运行没有一次落在正确区间。既然模型判不准，就把判断交给用户。

## 交互

1. 任务完成后，结果区列出**本次实际读到的原文句子**（`read_paper` 返回的 quotes）。
2. 用户勾选 1–2 句作为依据（最多 2 句），再输入问题。
3. 模型**只根据勾选的句子**写 2–3 句回答；引用就是勾选的那几句，无法改动。

选择这一步被完全移除：不再有"模型挑句"的环节。

## 结果（同一任务，2 个问题）

| 问题 | 用户点选 | 回答 | 引用 |
|---|---|---|---|
| 这篇论文要解决什么问题？ | 2112.07945 / 1（"Existing 3D GANs are either compute-intensive…"） | 「如何生成高质量、高分辨率且多视角一致性的3D图像」 | 1（= 点选） |
| 这篇论文的方法有什么特点？ | 2112.07945 / 2（"In this work, we improve the computational efficiency…"） | 「本文改进了3D GANs的计算效率和图像质量，但并未过度依赖这些近似方法。」 | 1（= 点选） |

两次都**对题**，且回答内容与所选句子一致。耗时 35.8s / 34.9s（主要是模型装载）。

非法点选（不存在的 quote_index）返回 **422**，不会进入生成。

## 为什么这次有效

- 失败发生在"选哪句"，不在"写答案"。把选句交给用户后，模型只剩"把两句英文转成中文回答"，这是 1.5B 做得来的。
- 引用由用户的点选固定，**模型没有任何编造引用的空间**。
- 候选句如果是空（没有引文），界面直接显示"本次没有可用的原文句子"，不会假装能答。

## 边界

- 这测的是**写作能力，不是选择能力**；证据由用户提供，不能拿这个结果说"模型会选证据"。
- 2 次运行，单篇论文，不构成样本。
- 界面复选框的点击没有在自动化里验证（沙箱没有浏览器自动化），已验证的是：JS 语法、样式、路由、422 校验、以及带 picks 的真实生成。
