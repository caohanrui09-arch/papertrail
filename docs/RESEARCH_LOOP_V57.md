# Papertrail v57：从真实问题到阅读记录

日期：2026-11-07（香港时间）。本轮为当前电脑的本地交互版，入口 http://127.0.0.1:8791/ 。

## 本轮可以做什么

1. 在搜索旁点“中文需求”，输入“多模态快慢思考”，生成英文术语。建议可以修改；点搜索才执行。原问题、术语映射和实际执行词保留在范围说明与调用轨迹中。未识别词和否定表达需要检查确认。这是固定领域术语辅助，不是全文翻译或 LLM 理解。
2. 通过首页新增专题或侧栏“专题阅读 → 多模态快慢思考”进入5篇候选。论文可搜索、对比、收藏、按实际收藏推荐、读取对应v1原摘要、保存阅读状态和笔记。
3. 搜索后点“记录需求”，主动记录未满足之处及已知目标ID。系统重新计算该条件下的返回结果，区分目录外、只搜了旧范围、时间限制、预设已见过滤、词项未匹配、未进前十和已返回。无已知目标时保持待核查；结果为空不等于缺论文。需求可标记待处理/已处理/归档，归档可改回。
4. “阅读清单 → 有笔记”搜索自己的问题或疑问。多个空格分隔词同时匹配，可直接回原摘要。中文短词使用参数化SQLite instr，较长词使用FTS5 trigram；临时索引仅含当前访客的笔记。
5. 候选栏点“阅读报告”，选1–20篇，选择是否附笔记与当前检索条件，预览后下载Markdown。来源从规范目录读取，原摘要缓存重新核验。报告不自动生成论文结论。JSON备份用于恢复偏好、状态与笔记，Markdown用于阅读分享。

## 真实需求的定向审查

用户在本聊天提供“多模态快慢思考”。通过既有固定版本arxiv.py获取一次官方API响应，审查后纳入：

| ID（均v1） | 工作 | 纳入理由 |
| --- | --- | --- |
| [2504.18458](https://arxiv.org/abs/2504.18458v1) | FAST | LVLM过度思考、按问题特点调节推理深度 |
| [2506.00806](https://arxiv.org/abs/2506.00806v1) | FOCUS | VQA快速直觉与审慎推理、按复杂度选择视觉提示 |
| [2511.16670](https://arxiv.org/abs/2511.16670v1) | DualMindVLM | VLM快慢双系统与自适应思考 |
| [2610.25999](https://arxiv.org/abs/2610.25999v1) | TempoMoE | 多模态MoE中识别、调节快慢思考专家 |
| [2610.15810](https://arxiv.org/abs/2610.15810v1) | L2T | 联合视觉计算方式与思考长度 |

排除同名噪声2103.16553：研究快双编码器与慢交叉注意力的文本到视觉检索，不直接回答VLM按难度控制推理深度。本次为助手基于官方原摘要的主题初审，不是独立真人相关性标注。论文中的效果数字是作者报告，本站未复现。

当前BM25查询`multimodal fast slow thinking reasoning`前5项覆盖这5篇。它是补目录后的单案例链路验证，不是留出质量评价，不报告完整Recall、真人NDCG提升或生产QPS。

## 私有空间、迁移和容量

新目录使用新命名空间SQLite文件；启动时在文件锁及事务内将旧6表复制一次，保留原随机凭据、修订号、收藏、阅读状态、笔记和时间。旧数据库不修改。目标有数据却没有迁移标记时拒绝覆盖；旧笔记超过新备份容量时整笔回滚，不截断文本。

旧目录v1/v2/v3 JSON备份可以导入，旧key下的记录必须实际属于旧目录。浏览器阅读位置可从已知旧key迁移；清除位置同时移除这两个已知key，防止旧位置复活。只保存参数、ID和滚动位置，不缓存结果或原摘要。

旧SQLite保留为升级时快照。切换后所有新写入进新文件，不能同时运行旧版写入，更不能把旧快照当作自动同步回滚。需要回退时先导出当前JSON备份，并明确核查新版论文的适配。

需求记录独立于v3备份，最多30条（含归档），独立CAS修订，导出审计JSON不包含Cookie、其他访客身份或笔记。每条16KiB、整份256KiB。报告最多20篇/256KiB；笔记每栏1000字，合计按完整v3备份预算限制。报告下载后其个人内容可以被拿到文件的人阅读，预览提供取消选项。

维持单进程、独立访客Cookie、同源校验、90次/分钟普通请求、30次重请求、20次写入、12活动请求、512KiB请求体、每命名空间32MiB数据库上限。不在运行时抓取论文、下载模型或调用付费LLM。旧快照另外保留，因此磁盘总占用可能含两个命名空间。

## 开源取舍

已比较jieba、pyahocorasick、Argos Translate、CPython re、SQLite FTS5和CommonMark的相关实现。采用已有标准库、SQLite和原框架；没有新增运行时依赖、复制上游源码或下载翻译模型。完整许可证、源blob、维护状态、适配成本和限制见`reports/stage57/research.json`。CommonMark规范为CC-BY-SA4，工具软件另有BSD式许可，不能统称整仓MIT。元数据获取复用固定arxiv.py，保留原响应与哈希，继续遵守节流规则。

## 启动、验证与演示

从任意工作目录启动（PowerShell）：

```powershell
& '<repo>\papertrail-workbench.cmd' start
```

`status`查看服务，`stop`仅停止该控制器拥有的实例。启动器自行进入项目目录，避免在`<home>`执行相对路径找不到脚本。

在项目根目录运行接口与迁移验收：

```powershell
.\.cache\stage39\runtime-secure\Scripts\python.exe -E -s -m scripts.validate_research57_delivery
.\.cache\stage39\runtime-secure\Scripts\python.exe -E -s -m scripts.validate_research57
.\.cache\stage39\runtime-secure\Scripts\python.exe -E -s -m scripts.validate_research57_tools
.\.cache\stage39\runtime-secure\Scripts\python.exe -E -s -m scripts.validate_research57_loop

node scripts/validate_research57_memory.mjs

```

浏览器验收使用localhost:8797和独立临时访客目录，实际8791空间不写入验收收藏、笔记或需求。原生Markdown下载的Blob链接、预览和内容已核验；未把浏览器下载事件另称为已验证。这里只验证本机桌面，没有线上HTTPS、第二台机器或多人负载结果。

约3分钟演示：中文需求生成与编辑 → 搜索5篇专题论文 → 打开FAST原摘要与v1链接 → 收藏后查看实际推荐依据 → 写笔记并搜索 → 选择论文预览报告 → 展示需求诊断与历史核心范围。测试笔记与需求应在隔离空间进行。
