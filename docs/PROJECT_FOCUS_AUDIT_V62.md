## 修正后的主线

项目定位：**面向论文发现的搜索与个性化推荐Agent，包含生成式检索/推荐的受控算法研究。** 网站只是同一后端的交互入口。广告尚无对应业务、数据及评价，不写成广告算法成果。

一个具体任务应能展示：用户问题与真实阅读画像 → LLM选择检索/推荐/读取工具 → 算法产生候选、分数与个性化排序 → 读取来源摘要 → 检查引用与完成条件 → 输出推荐及可复核执行记录。失败明确返回；固定流程保留为参照，不静默替代模型完成任务。

下一阶段优先交付一个贯通入口，而不是继续增加前端页面：

1. 复用既有统一工具协议、smolagents循环和状态/schema隔离，列明每个工具实际调用哪种算法及使用哪个目录/画像。
2. 把现有BM25、内容推荐及SAR/冷启动研究适配到共同候选、历史和过滤契约，记录真实召回来源、排序分数及兴趣锚点。训练用户画像与当前访客收藏分开，未知用户/论文明确回退。
3. 让LLM实际作工具选择、查询调整、选文与最终提交，并与固定流程同预算比较；不预先假定LLM更优。
4. 将共同后端的执行结果接回现有网站，展示算法和Agent的真实参与，而不把静态文案或预写轨迹当作推理。

生成式模型继续作为已冻结的研究臂；接入新目录前必须重新核对ID空间、监督、解码约束和公平对照，不能把SciFact权重、9000 SID和任意在线结果直接混用。新增模型/训练须先有归因和预算依据，当前不启动训练或RL。

## 验收必须分开

- 算法：共同语料/时点/用户历史下的NDCG、Recall或MRR及覆盖、冷热组、耗时；没有完整标注时不宣称完整Recall。
- Agent：任务与协议完成率、非法/重复调用、来源引用准确性、调用次数、token及端到端延迟。
- 集成：同一请求能追溯输入、模型提案、真实工具执行、算法中间结果、读取证据和最终输出。当前网站有按钮或137接口检查通过，不能替代以上两类效果证据。
