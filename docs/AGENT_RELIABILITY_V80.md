## 三、发现1：约束策略的失败不是预算太小，而是「一次被拒后预算被烧完」

| 组 | 次数 | 实际扣减预算 | 状态机拒绝次数 |
|---|---|---|---|
| 约束 完成 | 13 | 10 次用 3 次、3 次用 5 次 | 全部 0 |
| 约束 失败 | 4 | 全部用满 6 次 | 全部 ≥1 |

- 完成的运行从不触发拒绝，且 3 次调用（search/recommend → read → final）或 5 次（mixed 两轮）就够。
- 失败运行都不是「合法动作做不完」，而是先出现一次被拒提案，随后每次提案继续扣减同一个 6 次预算（`state_constraints.py:47-54`），直到 `charged>=6`。
- 预算归零后 `legal()` 返回空表（`:33`），`refresh()` 把 `agent.tools` 置空（`:93`），smolagents 于是报 `Unknown tool …, should be one of: .`，最后以 `AgentMaxStepsError` 结束。**真实原因（预算耗尽）被这条空工具表错误掩盖。**

## 四、发现2：两种可区分的失败机制

| 机制 | 次数 | 典型任务 | 首个被拒动作 | 现象 |
|---|---|---|---|---|
| M1 分支混淆 | 2 | mixed（evaluation-002） | `read_paper` 第二篇 | 已读 search 结果后，又读另一篇 search 结果；规则要求第二篇来自 `recommend_papers`，被拒后模型改去重复检索，预算耗尽 |
| M2 引用形状循环 | 2 | empty / 自定义需求 | `finalize` | 连续 5 次发送**完全相同**的 final_answer 载荷，错误提示不变，模型从不改正 |

### M1 实例（本机新恢复环境，evaluation-002，60.3 秒）

```
SENT     search_papers    {"query":"All in One: ...","k":3}
SENT     recommend_papers {"k":3}
SENT     read_paper       {"doc_id":"2203.07303"}
REJECTED read_paper       {"doc_id":"2206.07160"}   err=ID is unavailable/already read
→ 之后模型重复 search_papers，被框架当作未知工具（工具表已空），预算耗尽
```

问题有两层：一是模型没有记住「第二篇必须来自推荐分支」；二是错误文本 `ID is unavailable/already read` 把「不是当前可读分支」说成「已经读过」，而该 ID 从未被读过。

### M2 实例（阶段73 e73-empty，19.5 秒）

搜索返回 0 篇（`read_ids=[]`），正确的终局是 `{"citations":[]}`；模型却编造了两个不存在的 ID，并原样重发 5 次：

```
REJECTED finalize {"citations":[{"doc_id":"987654321","quote_index":0},{"doc_id":"234567890","quote_index":1}]}
REJECTED finalize （同一载荷，×3）
REJECTED finalize （同一载荷，×5）→ 预算耗尽
```

同样的模式出现在阶段71 的自定义需求失败里（`search_papers` + 5 次相同 `final_answer`）。**这是模型不根据错误反馈修正动作，而不是状态机判错。**

## 五、发现3：无约束策略的失败是「不终止」

`llm_agent` 7 次失败全部在 8 次模型调用 / 9 步后 `Reached max steps`，没有最终答案；9 次里只有 2 次完成。约束策略把完成率从 22.2% 提到 76.5%，但两者任务与阶段混合，不能据此声称约束带来语义能力提升；能说明的是：**约束提供了明确的终止结构，而失败点仍集中在模型对状态反馈的响应上。**

## 七、可选修复方向（均未实施，需重新冻结协议）

| 方向 | 内容 | 是否改变语义 | 代价与风险 |
|---|---|---|---|
| A 诊断文案 | 区分「未返回」「已读」「分支不符」三种拒绝原因；预算耗尽时给出明确的终止状态 | 会改变模型看到的文本，属行为改变 | 低代码量；历史可比性中断，需新协议 |
| B 拒绝不占同一预算 | 被拒提案单独计数，或保留 1 次纠错额度 | 改变预算语义 | 需要新的同预算对照，否则不能与历史比较 |
| C 分支状态显式化 | 在状态里直接给出「下一篇必须来自哪个分支」及带分支标签的可读 ID | 只改提示，不改规则 | 仍属提示变更，需新协议 |
| D 空结果规则显式化 | 状态里写明「本次无返回论文，final citations 必须为空列表」 | 只改提示 | 同上 |

不建议的方向：放宽 `readable()` 让任意已返回 ID 可读（会破坏 mixed 任务的「两分支」语义）；自动替模型补读或补提交（违反项目规则）。

**结论：当前约束实现没有发现逻辑错误；失败集中在弱模型对拒绝反馈不修正，以及失败提案与合法提案共用同一预算导致的一次错误即终结。上表 A–D 都是"改提示/改预算语义"，不是 bug 修复，必须先冻结新协议并重新对照，不能用历史数字比较。**
