# Papertrail 产品需求 v1

编制日期：2026-10-29。依据用户已表达的方向、已完成阶段24及当前代码整理；新增规则是下一轮开发与验收提案。本文区分已实现行为与待开发项，未把产品需求草稿当真人相关性标签。

## 1. 产品目标与范围

让研究者和算法学习者从主题出发，查找论文、用收藏建立兴趣、发现未读论文，并追溯到明确版本的原摘要。项目同时展示生成式检索、推荐冷启动和工具 Agent 的可核验实验，服务于个人使用与面试演示。

当前版本：本地网站，历史万篇 arXiv v1 目录，默认显式模式选择、BM25 搜索、内容推荐及固定工具流程。用户已确定后期分享；下一步先完善真人评价和可理解性，再准备公开演示。没有广告投放业务需求。

优先用户及任务：

| 用户 | 要完成的任务 | 成功标准 |
|---|---|---|
| 首次访问者 | 搜索自己正在学习的主题 | 获得可打开原摘要、ID/版本/链接齐全的结果；无命中时知道如何调整 |
| 有阅读积累的用户 | 用自己的收藏发现未读论文 | 下一次推荐反映当前收藏；已收藏和已屏蔽论文均被过滤 |
| 评审或面试官 | 理解系统做了什么、结果依据是什么 | 能运行真实链路，查看真实工具轨迹和推荐依据，区分研究结果与当前功能 |
| 人工评价者 | 确认需求与盲标候选相关性 | 看到需求、相同上下文和原摘要，能够按统一规则判断，未判断项保留空白 |

## 3. 核心使用流程与验收

### A. 从主题找到论文

默认进入“搜索论文”，输入框提示当前英文目录与支持的输入形式。用户可输入关键词或论文标题，提交后看到真实执行状态、候选、原摘要摘录及来源。空请求给出可理解的提示。无结果时建议缩短关键词或放宽主题。

**S01**：成功搜索的每个引用都包含论文 ID、明确版本和可访问来源；引用文本必须来自该版本原摘要。**S02**：无结果时结果区为空且无虚构引用，保留实际轨迹。**S03**：服务不可用、读取失败、取消和部分完成分别呈现，不把它们写成“已完成”。**S04**：当前不依赖用户知道 BM25、TF-IDF 或调用 JSON 才能使用网站；完整轨迹置于可展开的详情。

### B. 建立与修改自己的兴趣

默认“我的收藏画像”。收藏是明确正反馈；不感兴趣只屏蔽该论文。两者互斥，再次点击可撤销。阅读或查看来源本身不自动生成正负反馈。单篇移除、全部重置、偏好计数和保存失败均须有可见反馈。

**P01**：收藏后再次推荐，收藏论文不再进入未读结果。**P02**：屏蔽后搜索及推荐都过滤该论文。**P03**：撤销后重新参与候选，不保证进入 TopK。**P04**：重置须有明确确认步骤，取消保留偏好；确认后恢复无画像回退。**P05**：刷新和正常服务重启后保留偏好。**P06**：并发修改冲突提示刷新重试，不静默覆盖。**P07**：每个请求显示使用的偏好版本；新增偏好后旧结果保留，并提供更新推荐入口（待补直接入口）。

当前浏览器空间由 Cookie 标识。同一浏览器标签页共享空间；清 Cookie 后没有账号恢复。产品中的“重置偏好”仅清空当前偏好，历史会话仍保留当时快照。后续增加“清除全部个人数据”时必须单独说明范围及恢复规则。

### C. 理解推荐

推荐先说明使用自己的收藏还是流行度回退。内容解释显示实际相近的收藏论文和匹配词项；数值明细可展开。没有词项重合时明确说明零分排序依据。解释只支持对得分来源的理解，原摘要核验与语义相关性判断分别呈现。

**E01**：所有词项贡献之和与实际内容分数一致；所有收藏贡献之和也一致，允许浮点误差。**E02**：解释中的收藏来自该请求快照，不混入之后新增收藏。**E03**：无画像时显示回退原因和冻结训练期流行度依据。**E04**：由真人在小批任务中检查解释是否清楚、是否容易找到对应原文；记录不理解的原因，当前不预设或声称满意度提升。

### D. 组合需求

当前“搜索＋推荐”提供同一请求中的主题搜索与画像推荐，各自来源可辨认。这是两路结果和来源核验的固定流程。评价实验中的“查询＋画像融合排序”是另一种研究设置；页面与报告必须写明具体使用哪一种。将来若提供按兴趣排序的主题搜索，应作为独立功能进行同目录对照，避免把当前组合流程误称已实现融合重排。

**M01**：两个来源标签正确，重复 ID 合并时保留两路来源。**M02**：仅一路有结果时显示部分完成。**M03**：改变主题不得改变同请求使用的画像快照。**M04**：默认预算与最终引用限制继续遵循原固定流程。

## 4. 论文需求与真人评价

此次另生成24条双语精修草稿，覆盖8个主题×主题搜索/推荐/组合三种需求。原需求、原候选池和原标注工作表继续保留；新草稿使用新ID并记录父ID及修改依据。所有文本均为 assistant_refined_draft，等待人确认。

本机材料：[24条双语需求与逐条判据](../data/stage25-requirements/需求精修_24条.md)、[空白真人确认表](../data/stage25-requirements/human-review-blank.csv)。旧版操作参考 [人工标注协议](QUALITY_ANNOTATION.md)；新确认表是独立提案，字段和新ID不能直接导入原评分入口。

每条需求必须写明：要查找什么、核心约束、次要偏好、需要何种阅读上下文、何时算高度/部分/不相关。核心主题决定等级，次要偏好不能抵消主题不符。上下文仅使用任务提供的相同论文，不替用户假定其真实兴趣。

判级顺序：摘要明确满足核心要求，判2；能确定覆盖相关部分但未满足完整核心要求，判1；能确定不符合核心主题，判0。如果阅读者无法理解需求/论文，或证据不足以作任何可靠判断，则留空并说明。各条判据里的“摘要未说明”只有在已确认部分主题相关时才支持1，不把未知自动填成0或1。次要偏好不单独升降等级。

### 人工确认与修改

确认者先检查需求是否清楚、场景是否合理、能否仅凭允许的证据判断。可选择确认、拒绝、待澄清，并说明原因。模型可以起草和检查措辞；只有实际真人操作才能形成真人确认记录。修改请求正文、核心约束或判据后，创建新的查询/池版本并重新检索候选，不能沿用旧标签或原冻结指标。

### 标注页的下一轮需求

**H01**：默认展示需求、相同阅读上下文、原v1标题摘要及来源，隐藏算法名、名次和分数。**H02**：0不相关、1部分相关、2高度相关；无法判断可跳过并记录原因，标签保持空白。**H03**：草稿与提交分开，保存后可恢复；误操作可修改并保留修订记录。**H04**：提交需要判断者标识、带时区时间、human来源声明和依据；自动助手不代填人类身份。**H05**：评分前检查目标 split 的需求确认和池内判断完整性；不足时只报告覆盖。**H06**：先 tuning、冻结方法后评价后段，新增候选先补标；池外相关文献未知时不计算完整目录 Recall。

采用精修草稿后，下一轮应先从 tuning 的3个主题、9条需求开始确认和建池，保留其余15条作为后段草稿；旧后段已被项目反复使用，因此新文字和新候选池也不自动成为独立真实用户测试。

## 5. 数据、性能和运行要求

| 编号 | 可验收要求 | 验收证据 |
|---|---|---|
| N01 | 当前私人反馈、偏好和轨迹存本机忽略目录；不进入旧实验 | 路径/写入目标及旧资产 hash 核查 |
| N02 | 浏览器空间不能访问另一空间的历史、偏好、导出、取消及原文读取 | 两种 Cookie 身份的实际 HTTP 检查 |
| N03 | 桌面1280宽、窄屏390宽可完成搜索、收藏和查看来源；无横向溢出 | 实际浏览器操作与截图 |
| N04 | 真实工具事件和请求耗时来自实际执行；取消后已执行步骤保留 | 服务轨迹与页面对应 |
| N05 | 报告冷启动、首次装载、后续请求耗时和峰值内存，明确测量边界 | 指定机器/目录/并发/样本的资源报告；当前不承诺生产QPS |
| N06 | 可从任意当前目录以绝对路径启动；重复启动复用拥有的实例 | 从用户主目录实际启动验收 |

每次迭代只增加与变化相关的检查。现有功能演示成功、推荐分数可解释和真人相关性改善分别验收。

## 6. 算法与 Agent 决策门槛

- 搜索默认 BM25；生成式检索保留在实验展示。后续先诊断监督覆盖、ID目标和解码评分，再决定小规模对照，不直接扩训练。
- 推荐默认内容方法；新的融合或负偏好策略先冻结假设与配置，共享目录/时间/过滤再比较。
- Agent 默认固定流程；LLM 调度继续列为实验模式。重新研究前需要新的任务集与同预算对照，任务完成、错误、token和延迟一起报告。
- 没有真人标签时只报告功能、协议、覆盖、成本和已有描述性实验结果。排名随收藏变化本身不构成质量提升。

## 7. 分享版发布条件

先选择许可允许公开的论文文本与演示素材，建立来源/版本清单；排除私人训练反馈、个人偏好、原始响应缓存和测试轨迹。前端接真实远程 API，服务端实现 HTTPS、身份验证、数据归属检查、请求/并发/存储限额以及失败清理。

**D01**：在全新浏览器中可完成搜索→收藏→推荐→原摘要→引用，且不依赖开发者电脑的127地址。**D02**：两个访问者互不读取私人空间。**D03**：公开部署所需数据与依赖可按文档准备，配置不含本机绝对私密路径或密钥。**D04**：完成指定资源条件下的并发与恢复验收后才发布链接。托管平台与预算尚待选择；当前不擅自注册、付费或上传。
