# Papertrail：本地交互论文工作台

打开 [http://127.0.0.1:8767](http://127.0.0.1:8767)。Papertrail采用聊天工作台布局，连接项目原有的共同万篇论文服务；左侧是实际会话，中间是请求、工具执行和引用，右侧是候选论文及原v1摘要。

## 启动与关闭

从任意PowerShell目录运行，整行复制即可：

```powershell
& '<repo>\workbench.cmd' start
```

启动器先复用或启动原8766论文服务，再启动8767展示层，默认打开浏览器。双击项目中的workbench.cmd也可启动；脚本自动切换项目目录，不需要手工cd。重复start复用同一实例。

```powershell
& '<repo>\workbench.cmd' status
& '<repo>\workbench.cmd' stop
```

stop只控制本轮展示进程，检查PID/创建时间/模块/解释器归属，保留原论文服务和全部历史文件。操作时等待当前请求结束；本轮未承诺强制关闭后的在途请求恢复。自动验收使用start --no-open，避免重复打开浏览器。

当前需要已准备的私有目录、原响应及stage17独立CPU运行时。浏览器资源全部本地提供，没有外部字体/CDN脚本依赖，无需Node、npm或GPU参与日常启动。旧Qwen研究入口继续单独使用stage6环境。

## 怎么体验

1. 点击“体验完整链路”，会填入按训练信息固定hash选择的已知标题及组合模式；发送后可以看到真实搜索→推荐→两次读取→最终引用，共5次工具。
2. 也可输入英文关键词或标题，用“搜索论文”模式检索。目录为英文论文，当前没有自动翻译或自由意图识别。
3. 选择“为我推荐”后可以直接发送。设置中可切换训练画像用户和冷启动用户；后者明确显示流行度回退，不冒充个性化。
4. 点击引用卡片或右栏候选，查看原摘要、明确v1和原文链接。尚未读取的候选会新建独立来源会话，重新检索确认ID后读取，单列两次工具及真实轨迹。
5. 展开工具条或“调用轨迹”，查看实际参数/返回/耗时，并可导出本机JSON。历史从本机文件恢复；新会话不会删除历史。
6. “实验与证据”展示83项冻结事实的聚合结果与源字段；“从本地探索，到分享展示”解释后续部署边界。支持明暗主题、键盘发送/Escape关闭弹窗及窄屏原文抽屉。

## 真实执行及失败边界

默认执行原有fixed/ToolClient，推荐仍为content。页面没有运行LLM、生成思考文本或把规则轨迹称为模型规划；状态约束LLM实验的12/4/7等数字只在证据页说明原受控对照。

NDJSON事件由工具真正开始/返回产生，没有为效果伪造调用或加演示延迟。引用是原摘要子串；标题/摘要/URL按普通文本处理，外链只接受明确的https arxiv.org来源。来源核验不等于论文语义相关性或观点真伪。

无匹配结果会显示没有匹配，组合缺一来源时标记部分完成；异常保持错误和已执行轨迹，停止请求也保留实际记录。每个原会话沿用6总尝试/2检索/2读取上限；额外候选读取使用独立来源会话，不隐藏在原会话计数中。缓存命中不宣称重新执行工具，原读取会话轨迹仍可查看。

## 文件与接口

| 位置 | 用途 |
|---|---|
| web/papertrail/dist | 可独立静态托管的HTML/CSS/ES模块与带许可证的固定浏览器组件；无私人数据 |
| gsearch/workbench_service.py | 新增同源展示API，调用冻结论文服务；不改变算法/旧服务 |
| scripts/workbench_control.py | 本轮展示进程的隐藏启动、状态和归属核验 |
| data/stage23-web/runs、reads | 私有请求、独立来源会话、原始错误及缓存；不作训练反馈 |
| .cache/stage23 | 运行状态/日志与独立验收响应；持续运行状态不写入不可变交付收据 |
| reports/stage23 | 固定组件审计、HTTP/浏览器/最终验证收据 |

前端只使用同源`/api`，不在浏览器代码中绑定8766或机器文件路径：

| 接口 | 行为 |
|---|---|
| GET /api/config、/api/health | 历史时点、默认模式和真实后端就绪 |
| POST /api/runs | thread_id、mode、query、profile；流式实际工具事件与最终记录 |
| GET /api/threads、/api/threads/{uuid} | 本机交互会话及请求恢复 |
| POST /api/runs/{uuid}/papers/{id} | 本次返回ID的原摘要，主流程已读或独立会话读取 |
| GET /api/runs/{uuid}/export | 来源字段投影后的本地轨迹JSON |
| POST /api/runs/{uuid}/cancel | 请求停止，已执行步骤保留 |
| GET /api/evidence | 阶段22冻结83项源事实 |

请求的origin=verification仅用于将自动HTTP验收记录与网页历史分类，**不是身份或访问控制**。浏览器验收产生的会话同样只是开发记录，不能当真人需求/相关性标签。当前工作台是单机空间，没有公网多用户账号或租户隔离。

## 后期如何分享

前端的相对`/api`契约和静态资源已经分开。后续可以发布dist并由同域代理连接远程Python服务；仅把当前127.0.0.1链接发给别人，他们连接的是各自电脑，无法访问这台机器。

在线阶段需要另行准备许可允许的公开样例、远程模型/API资源、身份/访问限制、每用户历史隔离、请求配额与运维验证。原SAR/推荐服务需要实际Python计算与内存，不能仅上传前端就假称远程算法已运行。当前未上传反馈/原始响应/轨迹、未建立公网隧道、未生成在线分享链接；真实第二机器验收仍待后续资源。

## 验收范围

真实HTTP覆盖搜索/推荐/组合、冷用户回退、无结果和部分完成、独立来源读取/缓存、导出、输入/同源/Host边界；浏览器实际操作验证桌面与390像素窄屏。新CPU策略测试6项与旧CUDA环境125项回归分开运行，保留原57包环境，避免为测试安装httpx2或改共享依赖。
