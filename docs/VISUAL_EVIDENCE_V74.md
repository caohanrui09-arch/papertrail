## 三分钟只读演示

1. 在实验台历史记录选择“固定组合流程 · 已提交”，点“载入真实记录”。此操作不执行当前输入、不调用模型。候选图显示搜索与推荐各3篇、6篇去重候选、2篇成功读取、2篇最终引用。
2. 点搜索节点，定位原时间线并展开参数；点论文节点，定位实际候选；点引用节点，展开对应证据链。核对本次读取的完整原摘要、逐字摘录、quote_index、论文ID、版本和原始链接。
3. 切到“冻结预设”，选择搜索＋推荐预设，点“运行独立诊断”。这是已有CPU算法，不是模型任务。展开诊断区，查看共享池查询排序到画像重排的完整名次；点连线/ID查看变化，点“显示全部名次”恢复全图。示例池15篇，实际1篇进入、1篇离开Top10。
4. 打开评测页，查看4×3矩阵。点击失败格定位保留的原结果，再点“读取本条轨迹”。对照独立的Token与耗时条形图及原始成本表。

输入或画像变更会清空旧图；独立诊断不会被画成 Agent 看过的候选。不要为演示点击“执行当前任务”或“重新执行九次对照”，除非确实要另外启动真实推理。

## 实现与复用

`research74/server.py` 延续原实验台网关；实际worker仍为阶段71。阶段70逐步事件、原生EventSource、状态约束、参数拒绝、预算与引用核验不变。新作业/方案使用独立stage74目录；历史自定义结果由只读保留入口载入，不修改旧作业注册表。阶段73盲标数据与评测模块原样复用。

图形只做DOM/SVG显示适配，不实现新排名、检索算法、Agent循环或图布局求解。比较GitHub的D3-shape、React Flow与Observable Plot后，实际复用本地固定的D3-shape3.2.0 `linkHorizontal` 和D3-path3.1.0；官方npm包SHA-512已核验，完整ISC许可证与版本commit保留。React Flow需要新的React/状态依赖，Plot会引入完整D3体系，当前小型固定布局不采用。不是漏洞审计；没有宣称“无安全风险”。来源与取舍见notes、THIRD_PARTY_NOTICES和vendor-sources.json。

SVG节点支持Enter/空格、名次有文字表、矩阵是原生表格、所有状态均有文字，支持减少动效。桌面1600×1200已验收，手机布局与公网多人访问未验收。
