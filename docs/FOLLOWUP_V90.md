# 多轮追问 MVP（阶段90）

日期：2026-11-24。目标：任务完成后，用户可以就**本次已读的论文**继续提问，不重新检索。

## 机制（已跑通）

| 环节 | 实现 |
|---|---|
| 入口 | `POST /lab/jobs/{id}/followup {question}` → 返回追问 id；`GET /lab/followups/{id}` 取结果 |
| 论文范围 | 只从**已完成任务**的 `read_paper` 轨迹里取已读论文（doc_id/版本/标题/摘要/引文） |
| 检索 | **不提供任何检索工具**；追问只能基于已读摘要 |
| 解码 | 语法约束生成 `{"answer": string, "citations": [{doc_id, quote_index}]}`，`doc_id` 的 enum 就是本次已读集合 |
| 校验 | 引用必须来自已读 ID、不重复、`quote_index` 在范围内；不合格直接拒绝，不修补 |
| 页面 | 结果区出现"基于已读论文追问"输入框；提交后轮询并展示答案与引用 |

## 正式运行（2 次，任务 `29de6cc3…`，evaluation-000）

| 问题 | 状态 | 引用 | 耗时 |
|---|---|---|---|
| 这篇论文的实验设置是什么？ | complete | 2112.07945，quote_index=0 | 48.1s |
| 这篇论文的局限是什么？ | complete | 2112.07945，quote_index=0 | 47.1s |

（另有一次探索运行在协议冻结前完成：问"核心问题/关键设计"，同样以 1 条引用返回，46.1s，仅作流程验证，不计入协议证据。）

## 机制通过、质量不及格

- **机制正确**：两次都输出合法 JSON、引用都来自本次已读论文、没有触发任何检索、原始任务结果未被修改。
- **质量不及格**：两次回答都是同一句 `expressive hybrid explicit-implicit network architecture`，既没有回答"实验设置"，也没有回答"局限"。这更像模型从摘要里摘了一个短语，而不是回答问题。

原因判断（未单独验证）：

1. 1.5B 在"受约束 JSON + 长上下文"下倾向于给最短合法答案；
2. 提示只说了"严格依据论文"，没有要求**直接回答问题**、没有要求长度、没有给"无法确定时怎么说"的规则；
3. 单篇论文、摘要 900 字截断，信息量本身有限。

## 下一步（按成本排序）

| 方向 | 改动 | 预期 |
|---|---|---|
| 提示强化 | 要求"用 2–4 句直接回答问题；摘要无法回答时明确说无法确定；不要只给短语" | 0.5 天，最可能立刻改善 |
| few-shot | 给 1–2 个问答示例（问局限→给出处+结论） | 与上一条一起做 |
| 多篇对比 | 追问时把 2–5 篇已读摘要并列，支持"比较"类问题 | 需要任务先读多篇 |
| 换模型 | 3B 上探 | 带宽 2 小时，未做 |

## 边界

- 2 次正式运行不构成样本；只说明"机制可用、质量不可接受"。
- 没有做多轮记忆（每次追问独立，不带上一轮问答），这是 MVP 的刻意取舍。
- 追问不计入 Agent 的协议完成率，它是"读后问答"，不是任务执行。

## 复跑

```powershell
# 需要 8802 在跑，且有一个已完成的任务 id
$body = @{question='这篇论文的实验设置是什么？'} | ConvertTo-Json
Invoke-RestMethod "http://127.0.0.1:8802/lab/jobs/<id>/followup" -Method Post -Body $body -ContentType 'application/json'
Invoke-RestMethod "http://127.0.0.1:8802/lab/followups/<fid>"
```
