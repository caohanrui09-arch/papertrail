# 自定义论文需求 v71

2026-11-16。入口：[Papertrail 算法与 Agent 实验台](http://127.0.0.1:8802/)。8791 阅读工作台保持原样，本轮没有扩大目录、重新训练或连接访客收藏。

## 启动与操作

双击项目根目录的 `project-agent.cmd`，待服务就绪后打开上述链接。PowerShell 可从任何目录执行：

```powershell
Set-Location -LiteralPath '<repo>'
.\project-agent.cmd
.\project-agent.cmd status
Start-Process 'http://127.0.0.1:8802/'
```

启动器现指向 `research71.control`，继续使用已有两个隔离环境与本地固定权重；不自动下载模型或安装新依赖。启动阶段会检查冻结资产并拟合既有推荐组件，首次装载模型不计入页面的 Agent 执行耗时。该命令要求此前已准备好的项目环境，而不是全新电脑安装说明。

1. 选择“自定义需求”，输入完整问题，明确选择搜索、推荐或搜索＋推荐。
2. 选择服务提供的冷启动画像或冻结训练画像 A/B/C，点击“整理需求与检索词”。
3. 核对原问题、可编辑的实际检索词，以及展开区中的术语对应、未识别内容与限定条件。中文处理是已有领域词表辅助，不是完整翻译；需要时自行补齐英文关键词。
4. 勾选两项确认，再执行真实 Agent。输入问题或更换画像会使旧方案失效；编辑检索词需重新确认。方案在当前服务实例内有效30分钟。
5. 查看实际事件时间线、工具参数/返回、模型提案/拒绝、Token 与耗时。合法回答附实际读过的论文 ID、原摘要摘录、版本和链接。

可复核的目录内示例：原问题“帮我找几何感知3D生成的论文，并引用原摘要”，实际检索词改为 `Efficient Geometry-aware 3D Generative Adversarial Networks`。这只是链路演示，不是盲测查询。

## 范围与原始需求

- 每份方案保存完整原问题、词表版本/对应/未识别项、候选查询、编辑后的实际查询、两项确认、画像和服务端时间范围。模型输入保留原问题；搜索工具必须原样使用确认查询，改写会被拒绝，不替它修正。
- 全部方法仍使用冻结的10,000篇目录，服务端固定推荐时点 `2025-02-23T05:28:26.401006+00:00`，画像训练截止 `2024-10-27T18:52:32.337704+00:00`。这是既有实验快照，不能视作当前最新论文库。可用性、已读过滤和元数据版本沿用原服务。
- A/B/C 是17/3/35篇历史的既有训练画像；冷启动明确无历史、使用原生流行度回退。不是当前访问者的收藏，也不代表系统理解了访问者本人。服务不接受用户任填 `user_id`、日期或路径。
- 年份、排除、必须等语义限定保留并提示，**没有新增年份/主题/排除条件的程序化筛选**。原问题传给模型尝试遵守，引用核验不能证明全部语义条件已满足。用户确认也不是相关性标注。
- “候选从哪里来”沿用五种推荐方法，在同一画像/时点下比较；输入检索词不参与这组推荐排名。Agent 搜索结果与它实际选用的推荐结果分别记录在工具轨迹中。

## 执行与约束

实际调用原生 smolagents 1.22.0 / Qwen2.5-1.5B-Instruct；模型自己选择搜索、推荐、返回候选中的摘要读取和最终提交。默认状态约束 LLM，也保留原 LLM 入口；自定义任务没有固定流程代跑或九次预设对照入口。

`research71.runner` 版本化复用 v70 原生编排，只替换自定义提示词与客户端绑定；三个运行函数在归一化提示词路径后 AST 相同。冻结预设仍显式使用 `research70.runner` 与原提示词。参数 schema、合法动作、schema 实例隔离、计费次序与原文引用核验保持。

预算仍为6次应用动作、最多2次检索/2次摘要读取、7个 Agent 步骤、8次模型调用、30,000输入/1,280输出 Token、900秒作业超时。失败不是免费重试；约束拒绝与真正新增的网关执行记录分开。模型最后的未经核验文本不会当成回答；无合法提交就显示未完成。

原生 SSE、连续事件序号、游标重连及只读状态查询复用 v70；断流或刷新恢复同一作业，不自动重新 POST。**服务进程重启后尚不能恢复内存中的作业和方案登记**，磁盘输入/事件/结果仍保留；重新启动服务不等于自动续跑。保留每实例最多16个作业、64份方案、单作业3个/全局8个事件读者及本机同源限制。

无结果任务仅搜索一次、返回空列表。随后模型重复提出带占位论文 ID 的错误引用，5次最终提交在客户端被拒绝，另一次不可用动作提案也失败；应用动作计费到6次、模型调用到8次，最终步数耗尽。实际网关轨迹只有1次成功搜索，不能将“0次网关执行失败”误写为“没有错误”。未采纳其最终未经核验文本，没有补交空答案或新增调用。失败界面同时展示空结果、拒绝记录和预算耗尽。

- 31项自定义 HTTP 边界检查：空/超长/控制字符、任意画像/时间、额外字段、未确认、空查询、非法策略及跨站请求等；不启动模型。
