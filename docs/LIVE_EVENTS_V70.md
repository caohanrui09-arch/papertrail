## 实现与来源

- 原生 smolagents1.22.0 的 ToolCallingAgent、原参数schema/guard、原提示词和预算继续负责模型决策、执行和最终提交。没有新训练、自动补工具或替模型提交。
- research70.runner 从本项目冻结的 unified_agent/isolated 运行函数派生，仅增加被动客户端观测、原生 step_callbacks 和必要的模块/提示词路径适配。三函数 AST 在去掉这些适配后与原逻辑一致。原文件未修改，模型仍从原固定本地权重加载。
- 客户端工具返回后额外只读获取原网关快照，将新出现的原生条目逐项写入单写者 events.jsonl；原生 seconds、attempt、arguments 和 result 原值保留。失败条目照实保留，未新增执行轨迹的网关/guard拒绝单独记录。额外快照读取不计工具预算，但会增加少量观测开销，不把本轮耗时作为旧实验的新性能对照。
- 原生步骤回调记录实际工具提案、步骤错误、用量和约束状态，保留原 charge/refresh 顺序。事件不写私有模型输入消息或模型内部推理文本，提案不等于实际执行。
- 每条事件有连续序号、UTC时间、观测相对时间、任务/策略/run_index。日志及时flush；完整任务响应原子写入。半行或不完整UTF-8数据不投递。
- 复用已安装 Starlette StreamingResponse 和浏览器原生 EventSource，新增只读 GET /lab/jobs/{id}/events。帧使用SSE规范，Last-Event-ID与after游标取较新者；无效、未来游标明确拒绝。心跳只保持连接，不表示模型进度。全局最多8个读者、单作业最多3个，断开后释放。
- 浏览器按事件序号去重；当前页面断流由EventSource补发，刷新后从0重放原事件以重建视图，不重复启动模型。已完成任务最终以权威响应重整工具时间线；实时事件不完整时单独显示核对提示，不混淆任务完成与观测完整。
- 保留原两秒作业状态查询作为最终状态核对与故障恢复。多任务对照可跟随当前任务，或选择已完成记录；模型提案、执行失败和未执行拒绝分开显示。

调研比较 smolagents 原生callbacks、Starlette StreamingResponse 与 sse-starlette EventSourceResponse（BSD-3-Clause）。sse-starlette 当前环境未安装，增加它不是本次单向本地事件流的必要条件；实际复用已安装Starlette的HTTP流/断开处理与浏览器原生重连，只新增日志和协议适配。没有复制新上游源码或安装依赖，具体来源见 reports/stage70/research.json。
