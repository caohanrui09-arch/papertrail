# 空结果决策实验（阶段89）

日期：2026-11-24。问题：阶段88 的 8/8 里，空结果那两次是"唯一合法动作被 schema 强制"，**模型自己会不会接受空结果？**

## 设计

- 空检索返回 0 篇、且检索额度没用完时，合法动作**同时**包括 `final_answer`（提交空结果）和 `search_papers`（再查一次）。
- 约束解码保持开启，所以两个动作都是合法信封，不存在"格式失败"干扰。
- 只跑 `e73-empty` × 4（其他单元不受影响）。

## 结果

| 指标 | 值 |
|---|---|
| 第一次空结果后主动提交 | **0 / 4** |
| 第一次空结果后重试检索 | **4 / 4** |
| 最终完成 | 4 / 4 |

逐次动作序列：

```
#0 search -> search -> final_answer   (82.8s)
#1 search -> search -> final_answer   (17.9s)
#2 search -> search -> final_answer   (18.1s)
#3 search -> search -> final_answer   (18.0s)
```

## 解读

**阶段88 的空结果通过是结构性的。** 一旦给出真实选择，模型 4/4 都会再检索一次，而不是当场提交空结果；它只在第二次检索也空、只剩 `final_answer` 时才提交。

这不等于"模型完全不懂空结果"——它最终提交了空结果、没有编造引用（约束解码起作用了）。准确的表述是：

> 模型不会在第一次空结果时接受现实，但被约束解码挡住了编造；第二次空结果后才提交。

## 边界

- 重试用的是**同一个已确认查询**（custom 任务由客户端强制），所以这是"再查一次"而不是"换个词重查"。若允许改写查询，行为可能不同，本轮没测。
- 4 次运行不是样本，只能说明方向。
- 与阶段88 的 8/8 不可叠加解读：那次是"强制"，这次是"选择"。

## 处理

实验性的 `legal()` 改动已回滚，代码回到阶段88 状态：

- `gsearch/state_constraints.py`、`tests/` 的哈希与阶段88 收据**逐项一致**；
- 35 项测试通过；

## 对产品的含义

如果目标是"用户问了一个没有结果的查询，Agent 应该老实说没有"：

- 只靠约束解码不够（它只是强制合法动作）；
- 需要**产品层**设计：把"确认无结果"做成显式交互，或在提示里给出"第二次仍为空则必须提交空结果"的硬规则（当前行为恰好是这样，但它是被额度逼出来的）；
- 或者接受"再查一次"作为默认行为——对真实查询，第二次换个查询词是有意义的，值得单独做一轮"允许改写查询"的实验。
