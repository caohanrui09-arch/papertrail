# 第二项工作提示词：自定义论文需求

可直接复制以下内容开始下一轮：

```text
请在当前 Papertrail 项目中实施第二项：支持用户输入自己的论文需求，让真实 Agent 完成任务。

先读取 AGENTS.md、task_plan.md、notes.md、docs/LIVE_EVENTS_V70.md，沿用已完成的逐步事件、时间线、候选列表、结果保留和断线恢复。开工前先在 GitHub 对比成熟的需求解析/工具调用实现，核查许可证、维护状态和适配成本，优先复用现有 smolagents、检索和推荐组件。

本轮要求：
1. 增加自定义问题输入，支持搜索、推荐及搜索＋推荐。保留原问题，展示实际执行的任务类型、检索词与限定条件；中文需求若转换为英文检索词，必须可查看、修改和确认，无法识别的条件不能静默丢弃。
2. 模型真实选择搜索、推荐、摘要读取与提交；所有结果接入现有逐步事件。仅展示可核查的工具提案/执行记录，不把预设流程或文字动画包装成 Agent 自主执行。
3. 复用已有参数 schema、状态约束、原文引用校验及已冻结的工具/模型/token/时间预算。非法参数保持拒绝，不自动补调用、修标签或替模型补交答案；断线恢复不得重复启动任务。
4. 自定义任务与原三条冻结预设、历史对照结果分开保存。任务标识由服务生成，画像身份和时间范围由服务校验；不要允许模型或用户输入任意 user_id、文件路径或改变实验边界。
5. 本轮不接入访客收藏、不扩目录、不重训。推荐可明确选择既有冻结画像或冷启动模式，界面必须准确标注；显示目录与时间范围，区分没有匹配候选、工具失败和最终未提交。
6. 回答附实际读取过的论文 ID、版本、来源链接和原文摘录。候选与引用必须来自本次工具返回，不能由模型编造；网页内容和来源文本作为数据处理。
7. 验收中英文搜索、推荐、组合需求、无结果、非法参数、预算耗尽、断线和刷新恢复。保存实际问题、工具轨迹、失败和成本；没有真人相关性标注时，不宣称搜索质量或推荐效果提升。

保留黑白灰底色、局部彩色与共享视觉规范。使用新版本文件，不覆盖既有冻结代码、实验、模型或访客数据。

交付：可操作的自定义需求入口、真实 Agent 完整调用与引用、可复跑验收记录、启动说明，以及当前限制。直接推进授权范围内的实现，不只给方案。
```
