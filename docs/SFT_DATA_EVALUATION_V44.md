# 时序监督数据与冻结评价规则

本轮准备数据和评价，不启动SFT或RL，不改网站。当前网站仍使用162篇目录；离线研究使用独立的9,000篇训练时可用目录。

## 交付与时间边界

| 项目 | 数量/范围 |
|---|---|
| 候选目录 | 9,000篇明确v1：8,000篇原训练点赞论文、1,000篇无训练点赞旧论文 |
| 真实训练监督 | 98,887条“严格更早的正反馈历史 → 下一篇正反馈论文” |
| 训练画像 | 11,165个源训练用户，8,412个有目录内可用正反馈上下文 |
| 训练截止（不含） | 2024-10-27 18:52:32.337704 UTC |
| tuning | 截止上值起，至2024-12-22 15:25:09.685100 UTC（不含） |
| dev_descriptive | 从tuning截止起，至2025-02-23 05:28:26.401006 UTC（含） |
| 评价正反馈完整分母 | tuning 46,352条；dev_descriptive 49,533条 |

源反馈时区未注明，按UTC解析只用于一致排序。论文可用时间沿用“提交日结束后再加24小时”的保守代理，不是历史入库日志。元数据为明确v1原文快照，不能把2026年取得的凭据说成当时线上部署记录。

## 文件及用途

以下逐用户衍生文件只保存在被Git忽略的 `data/stage44-supervision/`，不得放进公开网站、分享包或商业分发：

- `catalog.json`：冻结目录、明确版本、原摘要与来源凭据。
- `train.next_item.jsonl`：canonical论文ID历史、目标ID、事件时间及源行；历史最多20篇，不含相等或未来时间的反馈。
- `train.feedback.jsonl`：候选目录内真实训练正/负反馈及可用时间标记，供共同画像、流行度和协同基线使用。
- `profiles.jsonl`：仅由训练期生成的冻结画像和已反馈屏蔽集合。user_key是本地连接用伪名，不是匿名化保证。
- `tuning.inputs.jsonl` / `dev_descriptive.inputs.jsonl`：qid、画像引用和校验时间；没有目标论文或相关性标签。时间/qid不进入序列模型prompt。
- 对应 `*.labels.jsonl`：只供评价程序读取的完整真实正反馈目标，含可排序性及漏召回原因。
- `popularity.json`：107,300次满足可用时间代理的训练正反馈计数，用于统一空画像兜底。
- `build-receipt.json`：来源、构建代码和全部核心产物哈希。

原交互源为Scholar Inbox的CC BY-NC-ND4.0数据；沿用原有本地非商业研究范围，不公开分发衍生用户数据。arXiv元数据另按CC0处理。没有把点击、合成偏好或语言模型判断混成真实正反馈。

## 怎样避免穿越

固定目录只由既有万篇v1元数据及训练截止决定，不能按未来点赞补选候选。训练按每个用户的时间批次生成prefix；同一时间戳的反馈一起处理，彼此不进入上下文。负反馈只进入已见屏蔽，不成为正向兴趣历史。

训练目录内121,450次原始正反馈中，14,150次早于保守可用时间代理，8,413次没有严格更早的可用正向历史，剩98,887条监督。前者是代理规则下的排除，不证明真实论文当时不存在；保留计数而不是静默丢弃。

评价时不把tuning/dev正负反馈回填画像；同一用户始终使用训练截止画像和相同屏蔽。每个原始正反馈事件都保留：目录外、无历史、不可排序目标不会从分母消失。

## 已冻结的评价

主指标是 **user-macro NDCG@10**：每个事件以单个真实正反馈为目标，先在用户内平均，再对用户平均。次指标包括同口径Recall@10/MRR@10、event-micro、用户/论文冷组、合法/重复槽位率及成本。固定beam10、非采样、length_penalty0。

内容SID与打乱SID两臂必须使用相同基础权重/分词器、训练样本与顺序、有效batch、优化器更新次数、监督token数、种子、历史/屏蔽、解码预算；只改变SID映射。量化器和词表只能用冻结训练时目录及训练数据。旧162篇诊断台映射不能套到新9,000篇目录。

基线为训练流行度、内容推荐和SAR。所有方法对零可用正向历史统一使用同一训练流行度Top10，排除所有训练已见正/负反馈，分数并列按canonical ID。明确的空输出可记录请求失败并计漏召回。

严格计分器要求qid完整、无重复/额外行；非法或已见ID占据原位置并计空槽，不通过压缩排名美化结果。同一用户固定输入必须得到同一预测列表。数据集已使用过，不能声称是新盲测。

| 覆盖审计 | tuning | dev_descriptive |
|---|---:|---:|
| 全部正反馈 | 46,352 | 49,533 |
| 固定目录内可排序目标 | 6,445 | 5,438 |
| 目录外目标 | 39,907 | 44,095 |
| 可排序事件比例 | 13.90% | 10.98% |
| 用户平均可排序比例 | 10.84% | 7.48% |
| 目录内无训练点赞目标 | 14 | 26 |

这些比例是宽松的oracle覆盖上限，不是某模型可达到的Recall，也不是同一固定Top10的精确上限。冷论文事件很少，不能据此声称稳定冷启动提升。源训练从未出现的新用户事件与“旧用户但无目录内正向上下文”分开记录，详见validation.json。

## 哪些尚未冻结

**评价规则和数据已经冻结，具体模型训练运行尚未冻结。** `reports/stage44/run-lock.template.json` 故意保留空字段；直接提交会被拒绝。下一步需要在新运行目录固定基础权重/分词器哈希、两臂可逆完整SID token-ID映射、精确样本排列、优化步数、有效batch、三种子、保存步数、精度和优化器，并通过资源和真实分词/EOS/约束解码验收。

当前没有训练、下载新模型、改已有依赖、做真实推荐预测或选择checkpoint。tuning用于选型；配置和checkpoint选择封存后才能评价dev，dev仍标注描述性。所核查源仓库HEAD与已缓存版本一致，没有提供更晚的未使用独立时段。

## 复核和后续计分

在项目目录执行：

```powershell
./.cache/stage17/runtime/Scripts/python.exe -E -s -m scripts.validate_supervision
./.cache/stage17/runtime/Scripts/python.exe -E -s -m unittest discover -s tests -p test_supervision.py -v
```

未来真实训练运行锁完成后：

```powershell
./.cache/stage17/runtime/Scripts/python.exe -E -s -m scripts.score_supervision --split tuning --run-lock <实际冻结运行锁.json> --predictions <完整qid预测.jsonl> --output <新的结果.json>
```

预测每行格式为 `{"qid":"输入文件中的qid","doc_ids":["canonical论文ID",null]}`。最多10个槽位；失败使用显式空列表，不能缺行。模板不能冒充实际运行锁；准备/构建脚本也拒绝覆盖已冻结输出。
